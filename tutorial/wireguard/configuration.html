Configuration Reference

What each setting of the server's wg0.conf and each line of a phone's .conf file does for the app. The cases are the rows of Test results that show it, on both phones unless a row says otherwise.

Where this page comes from

The behaviour comes from the cases named in each row, run against WireGuard on Ubuntu 24.04 with the server's own view of each (wg show and its log), and from the source code of both apps.

AddressThe server's address in the tunnel; the phones get one address each of its network.wg-download

A [Peer] with AllowedIPs = the phone's addressOne peer per phone: the server takes a handshake only from a key it has as a peer, and sends that phone only its own address. A key it does not have gets no answer.wg-download, wg-unknown-client-key, wg-guide-removed

LineWhat it does for the appCases

EndpointThe server's name or address and its port, which fill Server and Port on import; changed in the editor, they replace it. A name the app cannot look up: The WireGuard endpoint … could not be resolved. The app looks the name up for an IPv4 address.wg-endpoint-ip, wg-port-field-overrides-profile, wg-server-field-overrides-profile, wg-unknown-host
AllowedIPs = 0.0.0.0/0All of the phone's IPv4 traffic goes through the VPN.wg-download, wg-udp-probe
AllowedIPs = 10.66.66.0/24Only that network goes through the VPN, the rest the usual way: a DNS question over UDP left from the phone's own network, while the server's tunnel address answered through the tunnel.wg-split-tunnel

One key per phone

SettingWhat it does for the appCases
The same file on two phonesOne key is one peer to the server, which sends to the address it last heard that key from: with two phones on it at once, each loses the traffic the server sends to the other. While Android used the iPhone's file, the server's endpoint for that peer moved to Android for 14 seconds, and four of the iPhone's downloads timed out. Give each phone its own file (add-phone.sh).The guide's server, with the iPhone downloading with phone1.conf when Android connected with the same file

What the app always does

  • WireGuard over UDP, straight to the server: no proxy, no TCP.
  • Connected only after a handshake: up to 10 seconds per attempt (Auto Reconnect and Retry Times).
  • New sockets on every change of network, and the server's name looked up again.
