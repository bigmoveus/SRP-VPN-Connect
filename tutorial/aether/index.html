Aether

Aether connects to Cloudflare WARP, Cloudflare's free VPN service. In Public mode the phone needs no server and no account. In Private mode the phone connects to your own server over WireGuard, and the server carries its traffic on to WARP. SRP VPN Connect runs the Aether engine on iPhone and Android, and the server these pages set up runs it too. That engine is our fork of Aether (github.com/bigmoveus/Aether, tag v2.4.0-srp.2): Aether 2.4.0 with the app's changes (Configuration Reference).

The two modes

  • Public: the phone runs the engine. It registers a free WARP identity once and keeps it. It finds a WARP endpoint that answers and opens the tunnel to it. The phone's traffic leaves the internet at Cloudflare, with a Cloudflare address. The tunnel runs over MASQUE on HTTP/3 (QUIC over UDP), over MASQUE on HTTP/2 (TCP and TLS, where UDP is blocked), or over WARP's WireGuard. A WARP+ license and Tor are optional.
  • Private: the phone runs no engine. It connects to your server over WireGuard and reaches only one address there: the SOCKS5 port of the Aether engine in a Docker container, on the server's tunnel address. The engine carries the phone's traffic on to WARP. The phone only talks to your server, and the WARP identity is the server's.

How an Aether connection works

  1. The tunnel to WARP. In Public mode the engine on the phone opens it. In Private mode the phone first makes its WireGuard handshake with your server, whose engine keeps its own tunnel to WARP.
  2. The phone's traffic. The app takes the phone's packets and sends each connection through the engine's SOCKS5 port: the engine's on the phone in Public mode, the server's through WireGuard in Private mode. Names are looked up through it as well.
  3. The test connection. The app counts as connected once a test connection through the tunnel went through. It sends one every 20 seconds, and one at once when the phone changes network. Two failed in a row mean the tunnel stopped carrying traffic, unless traffic still came back through it in the meantime. Auto Reconnect then sets up a new session, or the VPN ends with the reason.

Where to start

  1. Install the app: on iPhone from TestFlight, on Android by building it from the source; see Installation. Our tests ran the code of commit 968a86a7 on both phones; on Android most cases ran on the build just before it, which differs only in how a test connection that fails while traffic still comes back is counted. A TestFlight build with this code is not out yet.
  2. For Public mode, add an Aether profile and connect: Setting up the app. Nothing else is needed.
  3. For Private mode, set up your server first: Aether server installs WireGuard and our Aether engine in Docker on Ubuntu 24.04, and makes a file for each phone.
  4. Every setting of the profile and of the server, and what it does: Configuration Reference.
  5. If it does not connect: Troubleshooting.

What was tested

Test results lists every case we ran on an iPhone and on an Android phone:

  • In Public mode: downloads and uploads over MASQUE on HTTP/3, on HTTP/2 and both, and over WARP's WireGuard; both directions at once; the Turbo endpoint scan; TLS Fragmentation; an invalid WARP+ license; WARP through Tor; and Tor only.
  • In Private mode, against our server: downloads and uploads; a wrong server key; a closed port; an unknown server name; damaged files; and the server's Aether container stopped.
  • For the connection itself: sleep in each On Sleep mode; a session that ends; network changes; a server that is away for a while or for good; Retry Times; and the log levels.
  • The server as Aether server sets it up.
