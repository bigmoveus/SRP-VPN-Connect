Configuration Reference

The server settings that change what the app's SSL VPN profiles do, what each field of a profile does on the wire, and the settings the app always uses. ocserv builds the server this page refers to; Test results has the case behind each statement.

Where this page comes from

Every server setting below was tested by changing it on our ocserv 1.2.4 test server, connecting both phones, and reading the session back with occtl; the case names in the tables are the rows of Test results. Settings this page describes without a case were left as the package sets them.

Server settings (ocserv.conf)

ocserv reads /etc/ocserv/ocserv.conf when it starts; after a change, systemctl restart ocserv, which ends the sessions that are open. A user's group file in config-per-group replaces the routes for the users of that group.

udp-port = 443DTLS over UDP. When it is reachable the VPN's packets go over DTLS; when UDP is blocked on the way, everything goes over the TLS connection and the app connects all the same.ocv-pass-download, ocv-tls-only-download, ocv-tls-only-full-duplex

On Ubuntu 24.04 ocserv cannot offer TLS 1.0 or 1.1 at all, because the system's GnuTLS turns them off; that case used another TLS server.ocv-server-tls13, ocv-server-tls11-only

What each profile field does

FieldOn the wire
Server TypeThe protocol: AnyConnect, F5 BIG-IP or Palo Alto GlobalProtect, all spoken by the same OpenConnect core (9.21). A type the server does not speak ends with The server did not answer as … server. Only AnyConnect was tested against a real server.
Server, PortThe app connects to https://Server:Port/. An empty Port is 443.
TLS Server VerificationOn: the server's certificate must chain to a root the phone trusts and be issued for the Server name. Before connecting, the app checks the certificate itself and shows a warning that can be accepted once. Off: any certificate is accepted.
Method, Username, Password / CertificatePassword: the app fills the server's login form; it answers a form at most three times and does not send a refused password again. Certificate: the app presents the imported client certificate during the TLS handshake.
Auto Reconnect, Retry TimesWhen the connection breaks, the app resumes the same session with its cookie: at once, then after waits of 2, 4, 6 … seconds. With Auto Reconnect on and Retry Times empty it keeps trying as long as the server keeps the session, and then logs in again. With Retry Times n it tries n times and then ends the VPN with Could not reconnect after n attempts. Before the first connection, Retry Times also repeats a failed login (Could not connect after n attempts.). With Auto Reconnect off a broken connection ends the VPN with Connection lost (auto reconnect is off).
Switch to Wi-Fi When AvailableWhen Wi-Fi appears, the app moves the running session to it: the connections close and the session resumes over Wi-Fi, without a new login.
On SleepStay keeps the connection while the phone sleeps. Pause closes it and connects again on wake. Off closes it; on wake the app connects again only with Auto Reconnect on, otherwise the VPN ends with The connection was closed while the device slept.
Log LevelNormal: the app's own milestones and OpenConnect's errors. Expert adds OpenConnect's progress lines and the routes. Debug adds the server's headers; the values of the server's cookies are written as <elided> at every level.
TLS FragmentationSplits the TLS ClientHello into several TCP writes; the TLS stream itself is unchanged. Auto: 43 bytes, then 256 bytes 3 ms apart (128 bytes, 10 ms apart, on cellular). Manual: First Chunk, then Following Chunks (32 and 256 when empty).

Settings the app always uses

  • The app's user agent is SRP VPN Connect v9.21 (occtl show user shows it), and it names its platform apple-ios on iPhone and android on Android.
  • It gives DTLS 60 seconds to start; until then, and whenever DTLS is not up, the packets go over TLS.
  • For GlobalProtect it does not use ESP (UDP); the tunnel runs over TLS.
  • The Android app routes IPv4 only: when the server also gives an IPv6 address, the log says so and the address is not used.
