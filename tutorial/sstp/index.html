SSTP

SSTP (Secure Socket Tunneling Protocol) carries a VPN connection inside HTTPS on TCP port 443. SRP VPN Connect connects to SSTP servers on iPhone and Android with the same SSTP and PPP code on both.

How an SSTP connection works

  1. TCP and TLS. The app opens a TCP connection to the server, directly or through a proxy, and starts TLS. It checks the server's certificate against the server's name.
  2. HTTP. Inside TLS the app sends one HTTP request, SSTP_DUPLEX_POST, and the server answers it. From then on the connection carries SSTP packets both ways.
  3. PPP. SSTP carries PPP. PPP agrees on the link, then logs the user in with one of the methods the profile allows: MS-CHAPv2, PAP or CHAP, or EAP (EAP-MSCHAPv2, PEAP, EAP-TTLS, TEAP or, with a client certificate, EAP-TLS).
  4. Crypto binding. After the login, the app sends the server a value computed from the login's keys and the server certificate it saw. A server that checks it, as Windows does, can tell that nobody in the middle replaced the TLS connection.
  5. Addresses. PPP gives the phone an IPv4 address and DNS servers. All of the phone's IPv4 traffic then goes through the tunnel.

Where to start

  1. Set up a server with one of the guides above.
  2. Install the app: on iPhone from TestFlight, on Android by building it from the source; see Installation. TestFlight build 35 (commit e91ff127) and later have this round's three SSTP fixes, which build 34 does not: EAP-TTLS with EAP inside against FreeRADIUS, the message when the server refuses the profile's login methods, and Retry Times after a lost connection. The connection log on iPhone needs TestFlight build 36 (commit 868a4df1) or later; build 35 does not write it.
  3. Add an SSTP profile: Setting up the app.
  4. If it does not connect: Troubleshooting.
