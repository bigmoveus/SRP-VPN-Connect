Configuration Reference

The server settings that change what the app's SSTP profiles do, what each field of a profile does on the wire, and the settings the app always uses. Windows Server, MikroTik RouterOS, SoftEther VPN Server and FreeRADIUS build the servers this page refers to; Test results has the case behind each server setting.

Where this page comes from

Every server setting below is one our test servers had on 6 November 2026, set up as their guides describe: Windows Server 2019, 2022 and 2025 with Routing and Remote Access, MikroTik RouterOS 7.25, SoftEther VPN Server 4.44 and FreeRADIUS 3.2.5. An iPhone and an Android phone ran the cases against them; the cases named mt-srv-… changed one router setting each. The case names in the tables are the rows of Test results. Settings this page describes without a case were left as the guide or the server sets them. The profile fields and the settings the app always uses come from the source code of both apps, as on Setting up the app, and from the cases.

Server settings

One table per server product, with the settings that change what the app does. Our Windows Server 2019 and 2022 check logins against local Windows accounts. Our Windows Server 2025 sends every login to FreeRADIUS, and our MikroTik router and SoftEther server send it the logins of their RADIUS users; FreeRADIUS's own settings are in the last table.

What each profile field does

The fields of Setting up the app, in the editor's order.

FieldOn the wire
Host, PortThe app opens a TCP connection to Host on Port, directly or through the proxy, starts TLS and sends one HTTP request inside it, SSTP_DUPLEX_POST. An empty Port is 443. Unless Custom SNI is on, the app checks the certificate against Host, so the server's IP address in Host usually brings the certificate warning: the certificate names the server, not its address. When the name does not resolve, nothing answers on the port or the TLS handshake fails, the app says Cannot reach the server (DNS/TCP/TLS failed). Check the host, port and certificate settings.
Allow Untrusted CertificateOff (default): before connecting, the app checks the server's certificate the way the tunnel will. It must chain to a root the phone trusts and be valid for Host, or for SNI Hostname when Custom SNI is on; otherwise the app shows DANGEROUS!, where Continue connects once without the check, Save and Continue turns this switch on, and Cancel does not connect. On: no check, also for the EAP server's certificate.
Method, Username, Password, CertificatePassword (default): PPP logs in with Username and Password by one of the methods below. Certificate: EAP-TLS with the client certificate imported from a .p12 or .pfx file that holds it and its private key; Username is optional and is sent as the identity.
Enable MS-CHAPv2, Enable PAP / CHAP (Less Secure)The PPP login methods the app offers, with the EAP methods below; the server picks one. MS-CHAPv2 is on by default, PAP / CHAP off. PAP sends the password inside the TLS tunnel without hashing it. When the server accepts none of the methods that are on: The server closed the connection during PPP negotiation. Check that it accepts one of the authentication methods enabled in this profile.
EAP Configuration: Enable EAP-MSCHAPv2MS-CHAPv2 inside EAP, without a TLS tunnel of its own.
Enable PEAP, Require Crypto BindingA TLS tunnel to the EAP server with EAP-MSCHAPv2 inside. The app checks the EAP server's certificate; one that does not chain to a root the phone trusts ends with The EAP server's certificate is not trusted: … With Require Crypto Binding, the connection fails unless the server proves with PEAP's crypto binding that the inner and outer sessions belong together; Windows NPS sends it, FreeRADIUS does not.
EAP-TTLS MethodDisabled (default), or EAP-TTLS with PAP or CHAP inside, or with EAP-MSCHAPv2 inside, which both EAP and MSCHAPv2 choose.
Enable TEAPTEAP without a secondary method.
Enable Identity Privacy, IdentityBefore the TLS tunnel is up, the app sends Identity (default anonymous) instead of the username.
Enable TLS 1.3, Disable TLS 1.0 & 1.1 (EAP)The TLS versions of the EAP tunnel, both on by default: TLS 1.2 or later, with TLS 1.3 offered. When the server ends the exchange on a TLS 1.3 offer, as Windows NPS does, the app tries once more with TLS 1.2.
Proxy: None, Manual (Address, Port, Username, Password), Auto (PAC URL)The proxy carries only the connection to the server; the traffic inside the VPN does not use it. None (default) connects directly. Manual tries SOCKS5 first and, when the proxy does not answer as SOCKS5, HTTP CONNECT on a new connection; the username and password go to the proxy when it asks for them. Auto fetches the PAC file over http or https, runs its FindProxyForURL for the server and tries the proxies it returns in order; the username and password go to the proxy the script picks.
Disable TLS 1.0 & 1.1 (Options)The TLS connection to the server uses TLS 1.2 or later. It applies to that connection only; each of our test servers connected with it on.
Auto Reconnect, Retry TimesAuto Reconnect (on by default) connects again 2 seconds after a connection that was up is lost; with it off the VPN ends with Connection lost (auto reconnect is off). Retry Times limits the attempts in a row, and empty means no limit; then the VPN ends with Could not reconnect after N attempts. Giving up., or, when the server cannot be reached, Cannot reach the server after N attempts. … A login the server refused is never retried.
Switch to Wi-Fi When AvailableOn by default: when Wi-Fi appears while the VPN is up, the app moves the connection to it. No test changed the network under a connected tunnel.
On SleepStay (default) keeps the connection while the device sleeps. Pause closes it and connects again on wake. Off closes it; on wake the app connects again only with Auto Reconnect on, otherwise the VPN ends with The connection was closed while the device slept.
Log LevelNormal: the milestones, such as the server the app connects to, the SSTP and PPP states, the addresses the server gave, and errors. Expert adds the TLS name the app checks, each PPP phase and the login methods the profile offered. Debug adds the SSTP client's and PPP's own lines. No level writes the password or TLS session secrets. When the app gives up on a connection, a line starting with SSTP: closing with reason: names the reason.
Enable Custom SNI, SNI HostnameSends SNI Hostname in the TLS ClientHello and checks the certificate against it, while the connection still goes to Host. It must be a bare hostname. With Custom SNI off, a name left in SNI Hostname is not used.
TLS Fragmentation, First Chunk, Following ChunksSplits the outgoing bytes of the TLS handshake into small TCP writes; the TLS data itself is unchanged. Auto sends the first 43 bytes on their own, so that the server name lands in a later write, then 256 bytes per write (128 on cellular) with a few milliseconds between writes. Manual: First Chunk (1 to 4096 bytes, default 32), then Following Chunks (1 to 16384, default 256). A larger size stops the connection before it starts: Invalid TLS fragmentation settings: chunk sizes out of bounds

Settings the app always uses

  • SSTP runs inside TLS on one TCP connection: after one HTTP request, SSTP_DUPLEX_POST, and the server's answer, the connection carries SSTP packets both ways, and they carry PPP.
  • After the login, the app sends the server a crypto binding value computed from the login's keys and the server certificate it saw. A server that checks it, as Windows does, can tell that nobody in the middle replaced the TLS connection.
  • It asks the server for IPv4 only. PPP gives the phone an IPv4 address and DNS servers, and all of the phone's IPv4 traffic then goes through the tunnel.
  • It never answers EAP-MD5, even when a server offers it first, because MD5 gives no key for the SSTP crypto binding and no proof of the server.
  • A connection that is not up 30 seconds after the start ends with Connection timed out. The server did not respond.
  • When the server stops answering PPP's keepalive messages, the VPN ends with Server stopped responding.
  • The iPhone and the Android app use the same SSTP and PPP code and show the same messages.
