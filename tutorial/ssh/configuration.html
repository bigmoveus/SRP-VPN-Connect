Configuration Reference

The server settings that change what the app's SSH VPN profiles do, what each field of a profile does on the wire, and the settings the app always uses. OpenSSH server builds the server this page refers to; Test results has the case behind each statement.

Where this page comes from

Every server setting below was tested by changing it on our OpenSSH 9.6 test server and connecting both phones; the case names in the tables are the rows of Test results. Settings this page describes without a case were left as Ubuntu sets them.

Server settings (sshd_config)

sshd reads /etc/ssh/sshd_config and the files in /etc/ssh/sshd_config.d/; for each setting the first value it reads wins, and the lines under a Match line apply only to the users it names. After a change, sshd -t checks the files and systemctl reload ssh applies them to new connections; sessions that are open keep running.

What each profile field does

FieldOn the wire
Server, PortThe TCP connection of the SSH session; a name is looked up on the phone. A name that does not resolve, a port that refuses or does not answer, and a port where another service answers each have their own message (Troubleshooting).
Host Key (SHA256)Compared with the SHA-256 of the key the server shows in the SSH handshake, before the password is sent.
UDP Relay (HEV)On: before the VPN comes up the app opens a channel to the relay and checks that it answers; then each UDP flow is a channel to the relay, which carries its datagrams inside the session's TCP stream.
Username, PasswordThe SSH login, encrypted by the session.
Auto Reconnect, Retry TimesWhen the session ends or breaks, a new SSH session 2 seconds later; Retry Times limits the attempts.
Switch to Wi-Fi When AvailableA new SSH session over Wi-Fi when it appears.
On SleepPause and Off close the session while the device sleeps; Stay keeps it.
Log LevelWhat the connection log shows; no level writes the password.

What the app always does

  • Each TCP connection of the phone becomes an SSH channel (direct-tcpip) to its destination, opened by the server; the server looks up names, as the app answers the phone's DNS queries itself with placeholder addresses.
  • Only IPv4 goes through the tunnel.
  • The tunnel's MTU is 1400.
  • A keepalive every 15 seconds; a session the server has not answered for 50 seconds counts as broken.
  • 15 seconds for the TCP connection and 20 for the SSH handshake and the login.
  • No proxy: the app connects to the server directly.
