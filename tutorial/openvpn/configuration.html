Configuration Reference

The server settings that change what the app's OpenVPN profiles do, what each field of a profile does on the wire, and the settings the app always uses. OpenVPN server builds the server this page refers to; Test results has the case behind each statement.

Where this page comes from

Every server setting below was tested on our OpenVPN 2.6.19 and stunnel 5.72 test server, in the configuration of OpenVPN server or in a second server instance that differed from it in the setting named, and both phones connected to it; the case names in the tables are the rows of Test results.

OpenVPN server settings

Each server configuration is one file in /etc/openvpn/server/, started as openvpn-server@NAME. After a change, systemctl restart openvpn-server@NAME applies it; the phones connected to it connect again by themselves when Auto Reconnect is on.

Transport and addresses

SettingWhat it does for the appCases
proto udp, proto tcp, portThe transport and port of the profile's remote line, which fill Server and Port. Both work; UDP is the usual one, TCP gets through networks that pass only TCP and is what stunnel carries.ovpn-udp-download, ovpn-tcp-download
topology subnetThe phone gets one address and the network's netmask.ovpn-udp-download
no topology line (net30, OpenVPN 2.6's default)The phone gets an address and a peer address instead of a netmask; the app sets it up that way, and the VPN works.ovpn-net30-topology

Keys, ciphers and certificates

SettingWhat it does for the appCases
tls-cryptThe profile's <tls-crypt> must be the server's key. With another key the server drops every packet: The server did not answer.ovpn-udp-download, ovpn-wrong-tls-crypt-key
tls-auth ta.key 0, auth SHA256The older way of signing the control channel works too; the profile needs <tls-auth>, key-direction 1 and the server's auth line.ovpn-cbc-tls-auth
data-ciphers AES-256-GCM:AES-128-GCM:CHACHA20-POLY1305The phone and the server agree on AES-256-GCM (the server's log: Data Channel: cipher 'AES-256-GCM').ovpn-udp-download
data-ciphers AES-256-CBCAn older server with CBC only: the app connects with AES-256-CBC and the server's HMAC. BF-CBC, DES and other legacy ciphers the app does not have.ovpn-cbc-tls-auth

remote-cert-tls client, crl-verifyEach phone needs a client certificate of the server's CA that is not revoked. A revoked certificate, or one from another CA, is refused by the server in the TLS handshake: The server stopped answering after the TLS handshake. …ovpn-revoked-certificate, ovpn-rogue-client-certificate
The server's certificateThe profile's <ca> must have signed it, and the profile's remote-cert-tls server asks for a server certificate. With another CA: The server's certificate could not be verified with the profile's CA (…).ovpn-wrong-server-ca

keepalive 10 60The server pushes ping 10 and ping-restart 60: the phone pings every 10 seconds and treats 60 seconds of silence as a dead path, then connects again with Auto Reconnect, or ends the VPN with The server stopped answering (keepalive timeout) (auto reconnect is off).ovpn-life-dead-path-reconnects, ovpn-life-dead-path-no-reconnect
explicit-exit-notify 1When the server stops or restarts, it tells the phones, which connect again at once. What the app always does

  • Data-channel ciphers offered: AES-128-GCM, AES-192-GCM, AES-256-GCM, ChaCha20-Poly1305, and the AES-CBC ciphers for servers that have nothing else.
  • No compression, whatever the profile or the server says.
  • The control channel's TLS as the profile says (OpenVPN 2.6 negotiates TLS 1.3); stunnel's outer TLS 1.2 or 1.3.
  • The server's address stays outside the tunnel; IPv4 goes through it as the server pushes.
  • A profile with several remote lines: the app tries them in order when the first does not answer, before it gives up on a first connection.
