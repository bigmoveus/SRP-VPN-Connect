Configuration Reference

What each setting of the server's awg0.conf and each line of a phone's .conf file does for the app. The cases are the rows of Test results that show it, on both phones unless a row says otherwise.

Where this page comes from

The behaviour comes from the cases named in each row, run against AmneziaWG's kernel module on Ubuntu 24.04 with the server's own view of each (awg show and its log), from a client with the app's AmneziaWG engine on the server itself (the lab rows), and from the source code of both apps and of AmneziaWG.

The generations of AmneziaWG

AmneziaWG added settings in steps; a server and a phone that share a step's settings connect. The app takes every step's settings, and a file of any step.

The server (awg0.conf)

SettingWhat it does for the appCases
ListenPortThe UDP port of the phones' Endpoint. A phone whose file names another port gets no answer: The server did not answer the AmneziaWG handshake …awg-download, awg-closed-port
AddressThe server's address in the tunnel; the phones get one address each of its network.awg-download
S1, S2The random bytes in front of the handshake's first message and of its answer. A phone with another value gets no answer.awg-download, awg-s1-mismatch
S3, S4The random bytes in front of a cookie message and of every data packet. A phone with another S4 (or without S3 and S4) gets its handshakes answered and none of its traffic: the app ends the VPN with The server answers the AmneziaWG handshake but none of the traffic: S3, S4 or H4 may differ from the server's.awg-download, awg-life-s4-mismatch, awg-life-s4-mismatch-no-reconnect
H1, H2The ranges the first four bytes of the handshake's messages are drawn from (a single number in AmneziaWG 1.0). Another H1 gets no answer.awg-download, awg-gen-1-0, awg-h1-mismatch
H3, H4The same for cookie messages and data packets. Another H4 is answered like another S4: the handshake, none of the traffic.awg-download, awg-life-h4-mismatch
HeaderProtectionKeyEncrypts the header fields WireGuard sends in the clear; the phone needs the same key. A phone with another key, or none, gets no answer.awg-gen-3-0, awg-hpk-mismatch, awg-hpk-missing
RandomTrailers = onRandom bytes after each packet; the phone must have it too, or the server does not answer. With RandomTrailers on, data packets whose random bytes fall in the H1, H2 or H3 range are taken for handshake messages and dropped, by the kernel module and by the app's engine alike: with ranges of 100,000,001 values the iPhone's download fell from 200 to 12 Mbit/s and Android's two downloads took 62.5 s instead of 3.8 s, and in the lab 12 to 15% of the pings through the tunnel were lost, against the kernel module and against amneziawg-go as the server; with single values in H1 to H4 nothing was lost. Use single values in H1 to H4 with RandomTrailers, or leave RandomTrailers off.awg-gen-3-1, awg-gen-3-1-ranges, awg-trailers-missing
DisableCookies = onThe server sends no cookie messages when it is under load. It changes nothing for a phone.awg-gen-3-1
MTUThe server's tunnel MTU. With S4, data packets are S4 bytes longer: 1420 less S4 keeps a full packet within a 1500-byte path, in both directions.awg-download
PostUp forwarding and NATThe phones reach the internet through the server, with its address: a DNS question over UDP to OpenDNS for the asker's own address came back with the server's address.awg-udp-probe
SaveConfig = trueawg-quick save keeps the phones that awg set added, and the obfuscation values: after a restart of awg-quick@awg0 the server still has both.The guide's server (AmneziaWG server, its source note)
A [Peer] with AllowedIPs = the phone's addressOne peer per phone: the server takes a handshake only from a key it has as a peer. A key it does not have gets no answer.awg-download, awg-unknown-client-key, awg-guide-removed
The peer's PresharedKeyOptional; when the server has one for a phone, the phone's file must have the same. A different one gets no answer.awg-no-psk, awg-wrong-psk

DNSThe name servers the phone asks while connected, through the tunnel.awg-download

S1 to S4, H1 to H4, HeaderProtectionKey, RandomTrailersThe server's values (see above). S1 to S4 are whole numbers from 0 to 65535, H1 to H4 numbers or ranges up to 4294967295; another value is refused before connecting: Invalid AmneziaWG config: H1 must be a number or a range such as 1000000-1999999. A damaged key: Invalid AmneziaWG config: the HeaderProtectionKey is not valid base64 (32 bytes).awg-invalid-h1, awg-invalid-header-protection-key
Jc, Jmin, JmaxJc junk packets of Jmin to Jmax random bytes before every handshake; the server drops them. Keep Jmax under the path's MTU.awg-download, awg-gen-1-0
I1 to I5Packets made from a pattern, sent before the junk packets: <b 0x…> bytes as written, <r N> random bytes, <rc N> random letters, <rd N> random digits, <t> the time. A pattern AmneziaWG cannot read is refused with its reason: AmneziaWG refused the configuration: failed to parse I1: unknown tag <x>awg-gen-1-5, awg-download, awg-invalid-i1
ContentPaddingAdditionRandom bytes added inside data packets, up to the largest packet sent so far.awg-gen-3-0, awg-idle-padding
RekeyAfterTime, RekeyTimeout, RejectAfterTime, KeepaliveTimeout, MaxHandshakeAttemptsWireGuard's timings (120, 5, 180 and 10 seconds, and 18 attempts), changed or randomized: a range picks a value each time.awg-gen-3-0
[Peer] PublicKeyThe server's public key (server.pub). Another key gets no answer.awg-wrong-server-key
PresharedKeyAs the server's for this phone; a damaged one: Invalid AmneziaWG config: the PresharedKey is not valid base64 (32 bytes).awg-download, awg-bad-preshared-key
EndpointThe server's name or address and its port, which fill Server and Port on import; changed in the editor, they replace it. A name the app cannot look up: The AmneziaWG endpoint … could not be resolved. The app looks the name up for an IPv4 address.awg-endpoint-ip, awg-port-field-overrides-profile, awg-server-field-overrides-profile, awg-unknown-host
AllowedIPs = 0.0.0.0/0All of the phone's IPv4 traffic goes through the VPN.awg-download, awg-udp-probe

PersistentKeepaliveA keepalive every so many seconds when nothing else goes; AmneziaWG also takes a range (20-30). Without it the VPN works the same. With padding and random trailers a keepalive is as long as a data packet; the app's check for a server that stopped answering allows for that, and idle sessions stayed up.awg-download, awg-no-keepalive, awg-idle-padding, awg-idle-trailers

WireGuard's files

An AmneziaWG profile connects with a plain WireGuard file to a server without obfuscation (awg-gen-none); to an AmneziaWG server such a file gets no answer (awg-wireguard-file). A WireGuard profile does not take a file with AmneziaWG settings: the editor refuses it at import, and a profile that has one ends with This configuration has AmneziaWG settings (…): use the AmneziaWG VPN protocol for it.

What the app always does

  • AmneziaWG over UDP, straight to the server: no proxy, no TCP.
  • Connected only after a handshake: up to 10 seconds per attempt (Auto Reconnect and Retry Times).
  • The VPN ends when the server answers two or more handshakes in 40 seconds and nothing else comes back while the phone sends.
  • New sockets on every change of network, and the server's name looked up again.
