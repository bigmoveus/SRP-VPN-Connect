Troubleshooting

Start with the checks below, then look up the message you see.

Where this page comes from

The messages and what triggers them were read from the source code of the app at commit a03a8bc2 and of WaterWall, and on Android at commit 0fc837e3. The commands are the ones we use on our test server.

First checks

1. Open the app's log

Tap the status text under the power button. For more detail, set Log Level to Expert or Debug in the profile's OPTIONS and connect again.

2. Is WaterWall running on the server?

Run these on the server as root:

systemctl status waterwall.service --no-pager
ss -ltnup | grep -i waterwall
Check The service is active (running), and your configuration's port is in the list: TCP for TLS, Reality, AEAD, no outer layer and QUIC Stream, UDP for KCP and QUIC Datagram. The program shows as Waterwall.

If the service does not start, its own messages say why:

journalctl -u waterwall.service -n 50 --no-pager
tail -n 50 /var/log/waterwall/core.$(date +%Y%m%d).log

3. Is the port open in the firewall?

ufw status numbered

The port and its protocol (tcp or udp) must be allowed. A KCP or QUIC Datagram chain needs a UDP rule; a TCP rule for the same number does not help.

4. Do the two halves match?

Compare the app's choices with the server file, layer by layer, using The server node for each app choice. The most common mistakes are a different port, a different UUID or password, a missing or extra layer (for example MUX on one side only), and an HTTP path that differs from /.

5. Can the server reach the internet?

When it connects, the app checks the tunnel by opening a test connection to 1.1.1.1 on TCP port 80, and for chains that carry UDP, a DNS query to 1.1.1.1. These go through your server, so the server must be allowed to reach 1.1.1.1 on those ports.

curl -sS -o /dev/null -w "%{http_code}\n" http://1.1.1.1/

Any HTTP status code means the server can reach it. On our server it prints 301. An error such as Connection timed out means something blocks the server's outgoing traffic.

When saving a profile

An alert titled Invalid WaterWall Configuration names the field to fix. The full list is in the UI guide.

Certificates

With TLS Server Verification on, the app refuses a server certificate that is not valid for the name it sends: the SNI, or the Server field when SNI is empty. If your server has a Let's Encrypt certificate for its domain, type that domain in Server and leave SNI empty. Turning verification off hides the problem but lets someone between you and the server pretend to be it, so fix the certificate instead.
