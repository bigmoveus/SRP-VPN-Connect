How it was tested

  1. Xcode installed the app's test build on the phone, and the test created the profile shown above in memory. It was not added to the app's profile list.
  2. The test connected the VPN and ran the app's own HTTPS check through the tunnel: a request to https://gstatic.com/generate_204, which must answer 204.
  3. For at least 90 seconds it ran 4 downloads of 16 MiB at the same time, over and over. The GeoIP cases downloaded from the reference server on port 28480; the others from the HTTPS test server.
  4. On chains that carry UDP, it then sent small UDP datagrams to the echo server for 90 seconds, at least 10 a second, and waited for each one to come back.
  5. It ran the HTTPS check again and disconnected.
  6. For the GeoIP cases, the harness then read the reference server's log, which records the address each download came from: our office address means the download went straight from the phone, the server's own address means it went through WaterWall.

A case passes only if the VPN stayed connected, the downloads ran the full 90 seconds with no errors or timeouts, both HTTPS checks succeeded, every UDP datagram came back, and every GeoIP download went the expected way.

Gaps and limits

  • TLS Server Verification was off and the SNI was localhost, because the test server used a self-signed certificate made for the run.
  • The UDP check sends small datagrams and waits for each echo; it shows that UDP works through the chain, not how fast it is.
  • Each case ran once, with one phone on one network.
