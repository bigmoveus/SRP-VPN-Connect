Retry Times used up ends the VPN with a message

Checks that when the server stays down, the VPN ends after the number of attempts in Retry Times and says why.

VERIFIED — TESTED SUCCESSFULLY  Tested on 1 November 2026 on the current app build against WaterWall 1.5.2.

Result

OutcomePassed: every check succeeded.
Test length63 seconds, including connecting and disconnecting

What the test does

  1. The profile uses Auto Reconnect on and Retry Times 1.
  2. The test connects. The test harness then stops the WaterWall copy on the server and does not start it again.
  3. The app must notice within 75 seconds that the connection no longer works.

Passes when the VPN ends within 90 seconds with a message that contains "after 1 attempts".

Test setup

The profile used the chain of the VLESS + TLS scenario, with the same server copy and profile settings, except the options the steps above change.

PhoneiPhone 12 with iOS 27.2 (build 24B119), on Wi-Fi
AppSRP VPN Connect 1.2.0, a Debug build of commit dfce868f, installed by Xcode for the test
Server programThe official WaterWall 1.5.2 release (Waterwall-linux-gcc-x64), run as a test copy on port 4097
TrafficAn HTTPS test server on the same machine, port 28483
NetworkOur office broadband line, over the public internet

Gaps and limits

  • The phone did not really sleep, and WaterWall inside the app did not really crash: a Debug build of the app accepts test commands that make the tunnel act as if it had. Stopping the server is real.
  • Each step ran once, on one phone and one network.
