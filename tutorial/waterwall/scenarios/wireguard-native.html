How it was tested

  1. Xcode installed the app's test build on the phone, and the test created the profile shown above in memory. It was not added to the app's profile list.
  2. The test connected the VPN and waited until iOS reported it connected.
  3. It ran the app's own HTTPS check through the tunnel: a request to https://gstatic.com/generate_204, which must answer 204.
  4. For at least 90 seconds it ran 4 downloads and 4 uploads at the same time, over and over. Each download fetched a 16 MiB file from the HTTPS test server. Each upload sent 16 MiB, and the server answered with the size and SHA-256 it received, which the test compared with what it sent.
  5. It ran the HTTPS check again and disconnected.

A case passes only if the VPN stayed connected, the test ran the full 90 seconds, every transfer finished, there were no errors and no timeouts, data moved in both directions, both HTTPS checks succeeded, and the HTTPS test server saw the transfers come through the tunnel (Direct mode and the GeoIP cases leave outside it by design and are not checked).

Gaps and limits

  • TLS Server Verification was off and the SNI was localhost, because the test server used a self-signed certificate made for the run.
  • For Reality, the cover site was a second TLS server on the test machine itself, not a public website.
  • The test measured TCP traffic. The UDP row in the result says whether UDP was tested; in this run it was not.
  • Each case ran once, for about 90 seconds, with one phone on one network.
  • The test copy of WaterWall used the harness's own small core.json with one worker, not our production core.json.
