Ping uses the phone's own network

Checks that the TCP ping on the home screen measures the real network, both before connecting and while the VPN is up.

VERIFIED — TESTED SUCCESSFULLY  Tested on 10 November 2026 on the current app build against WaterWall 1.5.42, the official release, unchanged.

Result

OutcomePassed: every check succeeded.
Test length19 seconds, including connecting and disconnecting

What the test does

  1. Before connecting, the test pings 1.1.1.1 on port 443, which answers, and 192.0.2.1 on port 443, an address reserved for documentation that never answers.
  2. It connects the VPN.
  3. It opens a TCP connection to 192.0.2.1 port 443 through the tunnel, which the tunnel accepts at once by itself.
  4. It pings both addresses again with the app's ping.

Passes when 1.1.1.1 answers and 192.0.2.1 does not, both before and while connected. If the ping went through the tunnel, 192.0.2.1 would seem to answer.

Test setup

The profile used the chain of the VLESS + TLS scenario, with the same server copy and profile settings, except the options the steps above change.

TrafficAn HTTPS test server on the same machine, port 28483
NetworkOur office broadband line, over the public internet

Gaps and limits

  • The phone did not really sleep, and WaterWall inside the app did not really crash: a Debug build of the app accepts test commands that make the tunnel act as if it had. Stopping the server is real.
  • Each step ran once, on one phone and one network.
