FAQ

Short answers, with links to the pages that explain more.

Setting up

Is there an Android version?

Yes, with the same WaterWall screens and options as on iPhone. It has WaterWall only so far and it is not in a store yet, so you build the APK yourself. We tested it on a Samsung Galaxy A55 and on the Android emulator. See Android.

Do I need to install WaterWall on my phone?

No. SRP VPN Connect contains its own WaterWall client. You only install WaterWall on your server; see Installation.

Which WaterWall versions does this guide cover?

The official WaterWall 1.6.0 release on the server, and the iPhone and Android apps, which contain their own WaterWall built from 1.6.0. Results with other server programs are not covered. See Versions we tested.

Do I need a domain name and a certificate?

For chains with TlsClient or QuicClient, yes: the server needs a certificate, and with verify on it must be valid for the client's sni. Our server uses a free Let's Encrypt certificate. RealityClient and EncryptionClient chains do not use a certificate of your own.

Which chain should I start with?

Getting Started walks through VLESS over TLS step by step, with the server file and the profile file to import.

Can I import a vless:// link or a QR code?

No. A WaterWall profile comes in as a plain WaterWall JSON file, with Import JSON, or is built node by node. There are no share links, QR codes or export.

Where are the server, UUID and SNI fields?

In the chain: the server's address and port are settings of the connector node, the UUID of VlessClient, the SNI of TlsClient. Open the profile, tap WaterWall, open the node and tap Edit node. A profile saved by an earlier version of the app was turned into its chain the first time the app read it; see Profiles saved by earlier versions.

Can apps on the phone use WaterWall as a proxy instead of a VPN?

Yes. In Settings → WaterWall Input, choose Local SOCKS5 proxy (127.0.0.1:1080) or Local HTTP proxy (127.0.0.1:8080) and connect: only apps set to use that proxy go through WaterWall, and the VPN carries nothing else. A profile that starts with HintPacketIN needs System VPN (TUN).

Can I use the app with an Xray or V2Ray server?

We only tested the app with WaterWall servers, so that is not verified. Note that WaterWall's MUX is its own format and is not V2Ray's Mux.Cool or XUDP.

Using the app

Why does the profile row say Ping: —?

No delay has been measured for that profile yet. Pull the list down to ping every profile, or swipe a row to the right and tap Ping. See How ping is measured.

Why can't the app ping my KCP or QUIC profile?

The ping before connecting measures a TCP handshake, and a chain that ends in UdpConnector, such as KCP, QUIC, ENet or GNS, does not reach the server over TCP; nor does a chain without a fixed server address. The app says so instead of showing a result. Connect to the profile to see its delay.

Where can I see what went wrong?

Tap the status text under the power button to open the app's log. Set Log Level to Expert or Debug in the profile's OPTIONS for more detail, then connect again.

Does the tunnel carry IPv6?

No. The WaterWall tunnel carries IPv4 only. On Android, apps also get no IPv6 route while the VPN is up, so IPv6 traffic does not leave outside the tunnel.

Does traffic to the server itself go through the tunnel?

On iPhone, with a HintPacketIN chain, no. The app keeps the addresses of the chain's connectors out of the tunnel, so a speed test or a site on that same address goes straight there over your normal network, and shows that network's speed. With a HintConnectionIN chain and Remote DNS (Fake IP) on, it goes through the tunnel. On Android it always goes through the tunnel.

Does the app support Fake TCP (FakeTcpHeaderClient)?

No, and a phone cannot run it without root. Fake TCP sends IP packets with a made-up TCP header directly onto the network, which needs a raw socket. iOS refuses a raw socket both in the app and in its VPN extension, and Android refuses it to an ordinary app: in our test each attempt ended with Operation not permitted or Permission denied. A VPN tunnel's packets only reach the phone's own system, so they cannot replace this.

What is Packet Encryption, and when should I use it?

It is WaterWall's packet mode encryption for Raw IPv4 chains, an EncryptionClient with packet-mode right after the HintPacketIN hint: each packet's TCP or UDP payload is encrypted separately with XChaCha20-Poly1305, adding 40 bytes per packet. The IP and TCP or UDP headers stay readable to anyone who can see inside the chain, and only TCP and UDP pass, so ping (ICMP) does not work through it. It helps when the chain has no other encryption. If you can choose, a stream EncryptionClient or TlsClient hides the whole stream. See the Configuration Reference.

Is the Obfuscator a kind of encryption?

No. ObfuscatorClient scrambles bytes with a fixed XOR key so they show no obvious pattern. Anyone who knows the method can undo it. BGP4 framing does not encrypt either. Use TLS, Reality, AEAD (EncryptionClient), QUIC or VMess for encryption.

What does Remote DNS (Fake IP) do?

When an app on the phone looks up a name, the tunnel answers at once with a placeholder address from 100.64.0.0/10 and sends the name itself into the chain, where the server, or a DomainResolver node, looks up the real address. WaterWall thus gets the name of every site, which a chain needs to route by name or to resolve names itself. It applies to HintConnectionIN chains with System VPN (TUN) as the input, and it is on unless you turn it off.

What happens when I turn Remote DNS off?

The app asks first, with Turn Off Remote DNS?, and turns it off only after Turn Off. The phone's DNS servers are then 1.1.1.1 and 1.0.0.1: apps look each name up there and connect to an IP address, so WaterWall no longer receives site names. Routing by domain and DNS routing in the chain stop working, even when they are set up in the chain. The one exception is a Router that reads the name from the traffic itself; see Configuration.

What does Auto Switch do, and why does nothing happen?

Auto Switch uses your other WaterWall profiles for the same server address as fallbacks. With only one profile for that server there is nothing to switch to, and a profile with exactly the same chain is not used. The option appears only for a chain with a fixed server address. See OPTIONS.

What happens when the phone sleeps?

That depends on On Sleep: Stay (the default) keeps the connection, Pause closes it and reconnects on wake, and Off closes it and reconnects on wake only when Auto Reconnect is on. On Android, sleeping means the screen going off.

How do I split the TLS ClientHello?

With a fragment object in the settings of the TlsClient or RealityClient; its keys are in the WaterWall documentation. A profile converted from the former TLS Fragmentation option has one: cuts at 32 bytes and then every 256 bytes for Auto, or the sizes you had typed for Manual.

What should the SNI be for Reality?

The name of the cover site your Reality server passes visitors to, as the sni of the RealityClient. Our server's cover is www.cloudflare.com, which converted profiles with an empty SNI use.

Server side

What must match between the app and the server?

The nodes, in the same order, on the same port, and the values listed in The server node for each client node: for example the UUID, the Reality password and salt, or the HTTP path.

Can one server run several chains?

Yes. Each chain is its own file on its own port, and all of them are listed in core.json. Our test server runs 44 of them. See Configuration Reference.
