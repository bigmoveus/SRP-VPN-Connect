Installation

This page installs a WaterWall server on Ubuntu exactly the way our test server is set up, then installs the app on your phone.

Where this page comes from

Every file, path, version and setting below was read from our test server on 1 November 2026: the binary, its release record and checksum, the service unit, core.json, the firewall rules and the certificate renewal hook.

The shell history of the original installation was not kept. The commands below produce that same recorded result, but they are not a transcript of what was typed back then.

What you will end up with

ItemLocation on the server
WaterWall program/opt/waterwall/Waterwall
Main settings file/etc/waterwall/core.json
One file per configuration (chain)/etc/waterwall/configs/*.json
TLS certificate copies used by WaterWall/etc/waterwall/fullchain.pem, /etc/waterwall/privkey.pem

Install the server

Run every command in this section on the server, as root, over SSH.

1. Download WaterWall

Download the official 1.5.2 release for 64-bit Linux, the same file our server uses:

mkdir -p /opt/waterwall/staging-1.5.2
cd /opt/waterwall/staging-1.5.2
curl -fLO https://github.com/radkesvat/WaterWall/releases/download/v1.5.2/Waterwall-linux-gcc-x64.zip

2. Check the download

This compares the file with the checksum stored on our server. It must print OK; if it does not, the file is not the one we tested, so do not use it.

echo "1d9ba7da4a3ab42b5685e5ecf03cf3d93a97ede5fd9fce8a12dbfc23e04a829a  Waterwall-linux-gcc-x64.zip" | sha256sum -c -

3. Unpack and install the program

apt-get install -y unzip
unzip Waterwall-linux-gcc-x64.zip -d unpacked
install -m 0755 unpacked/Waterwall /opt/waterwall/Waterwall
/opt/waterwall/Waterwall --version
Check The last command prints Waterwall version 1.5.2, as it does on our server.

4. Get a TLS certificate

Skip this step if you will only use chains without TLS (for example Reality or the AEAD-only chains). Our server uses Let's Encrypt with certbot in standalone mode and an ECDSA key. Standalone mode briefly runs its own web server on port 80, so port 80 must be free and open.

apt-get install -y certbot
certbot certonly --standalone --key-type ecdsa -d <SERVER_HOST>
mkdir -p /etc/waterwall
install -m 0644 /etc/letsencrypt/live/<SERVER_HOST>/fullchain.pem /etc/waterwall/fullchain.pem
install -m 0600 /etc/letsencrypt/live/<SERVER_HOST>/privkey.pem /etc/waterwall/privkey.pem

Let's Encrypt certificates expire after 90 days and certbot renews them by itself. This hook copies each renewed certificate to WaterWall and restarts it. It is the exact file from our server; save it as /etc/letsencrypt/renewal-hooks/deploy/waterwall and make it executable with chmod +x.

#!/bin/sh
set -eu
install -m 0644 /etc/letsencrypt/live/<SERVER_HOST>/fullchain.pem /etc/waterwall/fullchain.pem
install -m 0600 /etc/letsencrypt/live/<SERVER_HOST>/privkey.pem /etc/waterwall/privkey.pem
systemctl reload-or-restart waterwall.service

5. Write the main settings file

core.json holds the settings for the whole server and lists the configuration files to load. This is the content of our file. The configs list is shortened: our server loads 44 files, and you list only the ones you use.

{
  "log": {
    "path": "/var/log/waterwall/",
    "core": { "loglevel": "INFO", "file": "core.log", "console": true },
    "network": { "loglevel": "INFO", "file": "network.log", "console": false },
    "dns": { "loglevel": "INFO", "file": "dns.log", "console": false },
    "internal": { "loglevel": "INFO", "file": "internal.log", "console": false }
  },
  "misc": {
    "workers": 2,
    "ram-profile": "server",
    "mtu": 1420,
    "try-enabling-bbr": true
  },
  "dns": {
    "domain-strategy": "prefer-ipv4"
  },
  "configs": [
    "/etc/waterwall/configs/vless-tls.json",
    "/etc/waterwall/configs/vless-reality.json"
  ]
}
SettingWhat it does
workersThe number of worker threads. Ours is 2, one per CPU.
ram-profileserver lets WaterWall use larger buffers than on a phone.
mtuThe packet size for packet tunnels (raw IP, WireGuard). 1420 leaves room for the tunnel's own headers.
try-enabling-bbrAsks Linux to use the BBR congestion control for faster TCP.
domain-strategyprefer-ipv4: when a site has both addresses, connect over IPv4.
configsThe configuration files to load; each one is a complete chain on its own port.

6. Add the configuration files

Each file in /etc/waterwall/configs/ describes one chain. Getting Started writes the first one, VLESS + TLS. Each page under Verified Test Scenarios shows the server file for its chain, and the Configuration Reference explains what goes in a file.

7. Packet tunnels only: the NAT scripts

Skip this step unless you run the raw IP or WireGuard configurations. Those give the phone an address in a private subnet on the server. These two scripts let traffic from that subnet reach the internet through the server's own address (NAT), and remove the rule again when WaterWall stops. They are our files, with our subnet replaced by <TUNNEL_SUBNET> (for example 10.66.0.0):

#!/bin/sh
set -eu
iptables -t nat -C POSTROUTING -s <TUNNEL_SUBNET>/24 ! -o ww-wg0 -j MASQUERADE 2>/dev/null || \
    iptables -t nat -A POSTROUTING -s <TUNNEL_SUBNET>/24 ! -o ww-wg0 -j MASQUERADE
#!/bin/sh
iptables -t nat -D POSTROUTING -s <TUNNEL_SUBNET>/24 ! -o ww-wg0 -j MASQUERADE 2>/dev/null || true
chmod 0700 /opt/waterwall/nat-up /opt/waterwall/nat-down

8. Create the service

systemd starts WaterWall at boot and restarts it if it stops. This is our unit file, unchanged:

[Unit]
Description=WaterWall v1.5.2
After=network-online.target ufw.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/etc/waterwall
ExecStartPre=/opt/waterwall/nat-up
ExecStart=/opt/waterwall/Waterwall --config:/etc/waterwall/core.json
ExecStopPost=/opt/waterwall/nat-down
Restart=on-failure
RestartSec=3s
LimitNOFILE=1048576
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target
Not running packet tunnels? If you skipped step 7, delete the ExecStartPre and ExecStopPost lines. The service will not start when the scripts they name are missing.

9. Open the ports

Our server uses UFW, Ubuntu's firewall. Open SSH first so you do not lock yourself out, then port 80 for certificate renewals, then one rule per configuration port. These are three of our rules, with the comments we use:

ufw allow 22/tcp comment 'SSH management'
ufw allow 80/tcp comment 'ACME HTTP-01 renewal'
ufw allow 18443/tcp comment 'WaterWall VLESS TLS'
ufw enable
ufw status
Allow SSH before you enable the firewall ufw enable blocks every port without a rule, including SSH if it has none.

10. Start WaterWall

systemctl daemon-reload
systemctl enable --now waterwall.service
systemctl status waterwall.service
Check systemctl status shows active (running), and each listening port appears in ss -tulpn | grep -i waterwall, where the program shows as memfd:waterwall. If the service fails, read the newest file in /var/log/waterwall/ and see Troubleshooting.

Upgrading WaterWall

When our server moved to 1.5.2, the previous program, its service file and its release record were first copied to a backup folder (/opt/waterwall/backup-1.5.1/). To upgrade the same way:

  1. Download and check the new release as in steps 1 and 2.
  2. Copy the old program, service file and release record into a backup folder.
  3. Install the new program as in step 3.
  4. Run systemctl restart waterwall.service.

To go back, copy the backup program over /opt/waterwall/Waterwall and restart.
